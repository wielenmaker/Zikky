# Zikky

A small native code editor in Zig, built on [gooey](https://github.com/duanebester/gooey) (GPUI-style UI for Zig).
For components gooey lacks, use [gpui-kit](https://github.com/longbridge/gpui-kit) (Rust) as the design reference.

- Layout: file tree on the gray window background (left), code editor inside a rounded white container (right).
- Look: matches Onyx (`../onyx`, its light and dark themes); palettes in `src/theme.zig` (`theme.color`
  is the one in use), row geometry from Onyx's `file_tree.rs`.
- Appearance (`src/appearance.zig`): System, Light or Dark. It sets AppKit's appearance (title bars,
  menus, panels) and each window picks its palette as it renders; a macOS light/dark switch
  re-renders the windows, so System follows it live.
- Requires Zig 0.17. Build: `zig build`; run: `zig-out/bin/zikky [folder]` (default: the last
  session's folder, else the current directory, or from the app bundle the welcome screen);
  test: `zig build test`.
- App bundle (assembled by hand, `/Applications/Zikky.app`; `CFBundleName`/`CFBundleDisplayName` Zikky): `zig build -Doptimize=ReleaseFast`,
  copy `zig-out/bin/zikky` to `Contents/MacOS/zikky` (Info.plist: `CFBundleExecutable` zikky,
  `CFBundleIdentifier` dev.zikky.editor, `CFBundleIconFile` Zikky) and `assets/Zikky.icns` to
  `Contents/Resources/`, then `codesign --force --sign - /Applications/Zikky.app`. The icon is built
  from `logo.png` by `python3 design/icon.py` (Pillow, numpy; it also writes `assets/logo.png`): full-bleed (macOS 26 puts a legacy
  icon not shaped like its rounded square on a grey tile; the system rounds it); `design/icon.png`.
  The executable must be the Mach-O itself, never a script that execs it (LaunchServices then
  records the app with pid -1, so accessibility tools can't find its window). Started from a
  bundle, Zikky moves to the home folder (Finder starts apps in /).
- Welcome screen (`src/welcome.zig`): while no folder is open (`AppState.root` empty, e.g. the
  bundle's first launch) the main window shows the logo (`assets/logo.png`, embedded and drawn
  through gooey's named embedded images), Open Folder… (⇧⌘O) and the recent folders (up to 8,
  newest first, kept in `session.json`; a gone one leaves the list when clicked).
- The opened folder is the tree's single root, expanded. Clicking a file opens it in the editor; clicking a folder expands it. The open file gets the active pill.
- Right-click (or control-click) a tree row for a native menu (`src/row_menu.zig`): Open and
  Open in New Tab (files), Reveal in Finder, Copy Path, Copy Relative Path.
- The + at the sidebar header's right edge picks another folder (NSOpenPanel, deferred until the
  click is handled: its nested event loop would re-enter gooey's input lock) and replaces the tree.
- Tabs (`src/tabs.zig`, at most 16): each has its own editor (text, cursor, scroll, undo), kept
  while hidden and freed on close. Opening a file (tree click, quick open) replaces the shown
  tab, or shows the file's tab if it has one; switching focuses the editor.
- Tab bar (`src/tab_bar.zig`): a tab per open file, level with the traffic lights; the shown one
  is a grey pill like Rex's, the others share what it leaves and shrink to their logo when
  crowded; a click shows a tab, × (or ⌘W) closes it. The pill sits 7pt from the top and 7pt above the container (y=44); the
  editor's first line is 10pt inside it, and the tree's first row is centred on that line (at 13pt).
- Long names in the tab and tree are cut to fit and fade out (`src/fade_label.zig`; gooey boxes
  can't clip, so a gradient covers the cut).
- Gutter: 48pt at 13pt (scales with zoom), room for four-digit line numbers.
- File kinds (`src/file_kind.zig`): an icon and color per type (exact names such as Dockerfile,
  .gitignore, go.mod first, then extensions); non-editable files (images, lockfiles, archives,
  fonts, media) get a grey label, like Onyx's non-notes. Drawn by `src/file_icon.zig`.
- File marks (`src/file_marks.zig`, generated by `python3 design/marks.py src/file_marks.zig`):
  Zikky's own logo set for 27 languages and formats, not from Zed or a brand icon pack; each is one
  filled path on a 16-unit grid (nonzero rule), one color: colored in the tree and quick open, white
  on its color in the tab logo. Other kinds keep a Lucide outline. Edit the geometry in
  `design/marks.py`; `design/brochure.py` rebuilds the overview, `design/file-marks.pdf`.
- Editor font (`src/editor_font.zig`): Paper Mono Regular (default) or JetBrains Mono Nerd Font Mono,
  both embedded from `assets/fonts` (SIL OFL 1.1; the Nerd Font icons' licenses in
  `JetBrainsMonoNerdFont-README.md`), or the system's SF Mono / Menlo by name. ⌘+ / ⌘− change its
  size (8–32pt), ⌘0 resets to 13pt; both saved as settings.
- Syntax highlighting (`src/syntax.zig`, lexers in `src/syntax_code.zig` and `src/syntax_markup.zig`):
  a small lexer per language family: Zig, Rust, C-like, JS/TS, Python, Ruby/Lua, shell, JSON, YAML,
  TOML, INI/.env, HCL/Terraform, SQL, Dockerfile, Makefile (keys, sections, `$vars`), Markdown
  (headings, emphasis, code, links, markers; fenced code in its language), HTML/XML (with
  `<script>` / `<style>`), CSS/SCSS/Less and diffs. Tokens are lexed once into a cache (three: the
  shown tab, the quick-open preview, the settings preview), with the lexer's state, and each
  frame only draws the spans in view, so frame cost does not grow with the scroll position.
- Find (⌘F; `src/find.zig`, bar `src/find_bar.zig`): a pill floating at the top centre of the
  container. Every match is marked (`TextAreaState.marks`), the current one selected; Enter /
  ⇧Enter, ↑ / ↓, ⌘G / ⇧⌘G step, Esc closes. Smart case. ⌘F takes a one-line selection as the query.
- Command palette (⌘⇧P, View → Command Palette…; `src/palette.zig`, view `src/palette_view.zig`,
  commands `src/commands.zig`): a rounded card floating at the top centre (no dimming) over the
  editor: a search pill, the fuzzy-filtered commands (title, shortcut at the right, `›` for a
  submenu) and a footer of key hints. ↑/↓ (ctrl-n/p) select, Enter or a click runs, Esc or a click
  outside closes. Enter on a submenu row (Appearance) shows its choices in place of the list,
  with Back (esc) in the footer. Commands run the same `AppState` methods as their shortcuts;
  to add one, add a row to `commands.root`. Keys come through `key_capture`, so vim stays out.
- Quick open (⌘O / ⌘P; `src/picker.zig`, view `src/picker_view.zig`, matcher `src/fuzzy.zig`): the
  window dims under two separate rounded cards, the fuzzy-filtered files (matched letters in the
  accent color) and a highlighted preview headed by the file name. ↑/↓ (ctrl-n/p) select, Enter or
  a click opens, Esc or a click on the dim closes; its keys come through `key_capture`, so vim stays
  out. The main editor isn't drawn meanwhile.
- Settings (⌘,; window in `src/settings_window.zig`, content `src/settings_page.zig`, rows in
  `src/settings_panes.zig`): a second window, laid out and styled like Rex's settings window
  (search, panes, grouped rows, toggles), over the same `AppState`; changes apply to the main
  window live (`AppState.main`). ⌘W closes it; closing it frees its surfaces. Its Appearance pane:
  System / Light / Dark tiles drawn as tiny Zikky windows (`src/theme_tiles.zig`), a code sample in
  the editor's font and colors (`src/settings_preview.zig`), the font (a native pop-up,
  `src/font_button.zig`) and size. Saved to `~/Library/Application Support/Zikky/settings.json`
  (`src/store.zig`): appearance, font, font size, vim mode, wrap, line numbers, hidden files,
  excluded folders.
- Session (`src/session.zig`, `session.json` beside the settings): quitting or closing the main
  window (which closes settings and quits, like single-window Mac apps) saves the folder, expanded folders, open tabs (each with
  its cursor and scroll), the shown tab and sidebar; launching without a folder restores them. AppKit keeps the window frame
  (`autosaveFrame`). The settings' Session pane turns this off.
- Menu bar (`src/app_menu.zig`): Zikky (About, Hide, Quit ⌘Q), File (Open Folder… ⇧⌘O,
  Close Tab ⌘W), Edit, View, Window. Items with a keystroke replay it to the keymap, so a menu
  click and its shortcut run the same binding.
- Terminal (⌘J, View → Toggle Terminal; `src/terminal.zig`, view `src/term_view.zig`, session
  `src/term_session.zig`, keys `src/term_keys.zig`, pty `src/pty.zig`): a second rounded
  container below the editor's, part of the shown tab: each tab has its own, kept while hidden and
  ended with the tab (opening another file in the tab keeps it); with no tab there is one more. It
  runs `$SHELL -l` in the opened folder on a pty (`TERM=xterm-256color`); the state is Ghostty's
  terminal core (libghostty-vt, the `ghostty-vt` module of Ghostty pinned in `build.zig.zon`),
  fed by a reader thread and snapshotted (`RenderState`) under a lock as it renders. Cells are drawn
  as rows of text runs in the editor font, each run as wide as its cells; ANSI 0–15 come from the
  theme (`Palette.ansi`). Keys go through Ghostty's encoder (application cursor keys, Kitty
  protocol…); ⌘V pastes (bracketed), other ⌘ keys stay shortcuts. ⌘J opens and focuses it, or
  closes it when focused; a click focuses it; the wheel scrolls back; drag the gap above it to
  resize; `exit` closes it. Not yet: selection/copy, mouse reporting, bold faces.
- Keys and clicks (`src/keys.zig`, the window's `key_capture`) go to quick open while it shows,
  then the command palette, the terminal, the find bar, and vim.
- ⌘\ or the panel buttons hide/show the sidebar; hidden, the container fills the window and
  its top row holds the show button beside the traffic lights (like Onyx).
  In full screen (no traffic lights) the sidebar's hide button and the show button move to the edge (`src/titlebar.zig`).
- Editing: ⌘⌫ / ⌥⌫ delete to line start / previous word (⌘⌦ / ⌥⌦ forward); ⌥←/→ stop at
  punctuation, like macOS. Long lines soft-wrap (at the last space, 16pt before the container's
  right edge); only a line's first row gets a line number.
- Vim mode (`src/vim.zig`, motions in `src/vim_motion.zig`; no Zig vim package exists): starts in
  normal mode with a block cursor; i/a/I/A/o/O, v/V, counts, h j k l w b e 0 ^ $ gg G { } f t F T,
  d/c/y (+ dd cc yy D C Y S x X s), text objects (iw aw i" a" i( a( i[ i{ i< …), p/P, r, J, ~, u / ctrl-r, ctrl-d/u,
  `/` and `?` (the find bar; Enter goes to the match, Esc returns), `n` / `N` (motions, so `dn` works).
  Yanks also go to the clipboard; ⌘ shortcuts pass through. Not yet: `.`, macros, `:` commands.
- Keep code minimal; one small component per file.

## Vendored gooey

`vendor/gooey` is gooey `3f69825` with local changes (full diff in `vendor/gooey.patch`, grouped
as upstream PRs in `vendor/GOOEY-CHANGES.md`),
made so Zikky renders like Onyx (GPUI):
- Extra text face selected by `font_id` (`TextSystem.font_id_mono`), loadable from font bytes
  (`loadExtraFontData`, clears the glyph cache); the code editor draws with it.
- Key names `=`/`equal`, `-`/`minus` and `\`/`backslash` in keystroke parsing.
- Code editor `highlighter` callback (style/component prop); highlight spans color the text
  itself (`TextAreaState.color_spans`) instead of drawing backgrounds.
- ⌘/⌥ backspace and forward delete; word boundaries skip punctuation (macOS).
- Click-to-cursor only measures at codepoint boundaries (upstream panics clicking past a
  multi-byte character).
- Horizontal scrolling in text areas/editors: wheel `delta.x`, cursor reveal, clamped to the
  widest visible line (`TextAreaState.scrollBy`, `content_width`).
- macOS wheel deltas reach widgets in points: precise trackpad deltas stay 1:1, a line-based
  wheel is scaled by `wheel_line_points` in `input_view.zig`, and text areas scroll by that
  delta without the old ×20.
- Wheel scrolling (`TextAreaState.scrollBySmooth`): line notches ease toward the target
  (45ms time constant); trackpad input (`ScrollEvent.precise`, from its first event) and
  trackpad-rate events are resampled: their targets are kept with the
  input's own time (`NSEvent.timestamp`, `ScrollEvent.time_us`; arrival times jitter) and each
  frame interpolates them behind its presentation time by the display link's lead (averaged)
  plus the recent longest event gap (rises halfway to a longer gap, decays 1/32 per event), so it
  adapts to 60–120Hz and to the event rate (a fixed 24ms read ahead of the input at 60Hz, so
  frames snapped to the latest event: 12/12/6pt steps). The applied delay is slewed (per frame at
  most +1/4 or −1/16 of its interval): an average that jumped after each late event stalled one
  frame and doubled the next. Each frame averages the input over the event gap before its read
  time: a trackpad's deltas are smooth but its timestamps jitter ±2ms around its ~16ms cadence,
  so a point read jumped speed ~10% at every event (real trace: frame step error 21% → 10%,
  ~8ms more lag). A stream holds its last sample through
  gaps up to 60ms (a VM's events jitter 10–30ms apart) rather than restarting. Events land unevenly against
  vsync, and easing that hid it needed ~45ms of lag (input to screen: 69ms before, ~40ms now).
  The frame driver keeps requesting frames until it settles. Cursor reveals and programmatic
  scrolls cancel it and become the new target. Steps use the frame's presentation time
  (display link `in_output_time`, `TextAreaState.frame_time_us`), not the callback's wall
  clock, whose jitter made uneven steps. Frames are presented at once: timed presents
  (`presentDrawable:atTime:`) evened out arrival on a 120Hz panel but in a VM stalled
  `nextDrawable` for its full 1s timeout at the start of every scroll gesture, and cost ~40ms
  of lag (60Hz VM, input to screen: ~90ms timed, ~50ms at once, no visible unevenness).
- `TextAreaState.revision` bumps on every buffer change so derived caches (the syntax spans)
  know when to re-lex.
- Soft wrap (`soft_wrap` editor prop): the line index holds visual rows (`wrap_cols`, monospace
  columns) and each row's text line (`row_lines`), so cursor/selection/clicks/scroll follow them;
  the gutter numbers text lines. The editor rewraps, then takes the frame's scroll step
  (`TextAreaState.stepScroll`), before drawing the gutter, line highlight and syntax spans, so a
  resize can't leave them on the old rows and while scrolling they don't trail the text by a frame.
- Text runs longer than `MAX_GLYPHS_PER_RUN` (1024) are drawn in chunks (upstream asserts).
- `Window.key_capture`: sees key events before focused widgets (Zikky's vim layer);
  `TextAreaState.select` places the cursor/selection and `cursor_block` draws a block cursor.
- Native menus (`platform/macos/menu.zig`): `setMainMenu` builds the menu bar (items send an
  AppKit action or replay their keystroke via the view's `gooeyMenuKey:`); `popUp` shows a
  context menu at the mouse and returns the picked index (nested loop: call it deferred).
- Bold text: `ui.TextStyle.weight` semibold+ draws with `TextSystem.font_id_bold`, an extra face
  loaded by name (`loadExtraFont`; Zikky loads `.AppleSystemUIFontDemi`). Key name `,`/`comma`.
- Quitting runs the window's close callback (`applicationWillTerminate:` in the window delegate);
  `PlatformWindow.autosaveFrame` wraps `setFrameAutosaveName:`.
- Multiple windows (Zikky runs on `runtime.MultiWindowApp`, quit policy `last_window_closed`):
  `AppWindowOptions.traffic_light_position`; one render lock for all macOS windows (they share
  the text system, whose active font is switched mid-render, and each renders on its own display
  link thread); shared-resource windows are initialised in place (the a11y bridge points into the
  window) with the patched fields set; a window's teardown owns its NSWindow until then
  (`releasedWhenClosed` off), releases its view (and so its Metal layer), and clears the view's
  pointer first; views accept the first mouse click, so a click in the other window acts at once.
- Focused text widgets take only the ⌘ keys they use (A C V X Z, arrows, deletes); others such as
  ⌘Q / ⌘H reach the menu bar (upstream swallowed every ⌘ key).
- `Window.mouse_down`: the press being dispatched, so click handlers can tell a right click.
- `traffic_light_position` window option (macOS), re-applied on `windowDidUpdate:` because AppKit
  re-lays out the titlebar after a launch from an app bundle.
- Scrollbar style props reach text areas/editors (upstream drops width and colors); editors also
  take `scrollbar_padding`. Zikky's bar: 6pt, no track, 5pt padding, so its 16pt lane is the wrap margin.
- On-demand rendering (macOS): `benchmark_mode` off, `requestRenderAfter` keeps a real deadline,
  and `setScene` no longer re-requests a render from inside a render (it re-rendered every vsync,
  ~25–55% CPU idle). During a scroll gesture the window presents every vsync
  (`scroll_render_until_ms`): event delivery and the display link are not phase-locked, so
  on-demand rendering otherwise skips a frame and the next one moves twice as far.
- Two drawables while idle, three while scrolling (`setDrawableCount`): with two, `nextDrawable`
  waits for the one on screen and ~10% of 120Hz scroll frames dropped; idle, the third
  window-sized IOSurface (16 MB at 1280×820 Retina) only costs memory, and is freed on the next
  render after the count drops.
- Quad shader: premultiplied border blending and 1-device-pixel antialiasing.
- Shadow shader: GPUI's gaussian shadow; fixed double-applied offset.
- Glyphs: GPUI's color-based font-smoothing dilation (smoothing stays on at level 0),
  origin quantization, 16pt base face and logical-size rasterization.
- Canvas gradient fills (`fillPathLinearGradient` / `fillPathRadialGradient`) honor the canvas's
  reserved draw order, like `fillPath`; the sidebar's fade gradients used to paint above the
  quick-open card.
- Text widgets draw with their z-level: each level's inputs, text areas and editors are drawn
  once its commands are, so a floating box above covers them (upstream drew them after
  everything, so text showed through the find bar).
- `TextAreaState.marks` / `mark_color`: ranges filled behind the text like the selection (find
  matches), only for the visible rows.
- Appearance (`platform/macos/appearance.zig`): `set` NSApp's appearance (or follow the system),
  `isDark` (an atomic, read while rendering off the main thread); views re-render and update it
  on `viewDidChangeEffectiveAppearance`.
- `menu.popUpSelect`: a pop-up with the current item checked and opened under the mouse.
- `ui.TextStyle.mono`: text drawn (and measured) with `TextSystem.font_id_mono` (the terminal).
- `Window.key_capture` also sees mouse presses, drags, releases and wheels (the terminal panel and
  its divider); key name `` ` ``/`grave`.
- Replacing an extra face (`loadExtraFontData` / `loadExtraFont`) also invalidates the shape and
  measure caches, which key on the slot's address: another font in the slot reused the old
  glyph ids (switching Paper Mono to JetBrains Mono drew garbage).
- Each window sets its own scale on the shared text system and SVG/image atlases as its frame
  begins (upstream set the first window's once, so text on a 2x display drew half-size); their
  keys carry the scale, so a scale change no longer clears them.
- Mouse presses go to a floating (`z_index > 0`) element over a text area or code editor before
  the widget under it (the command palette over the editor).
- Glyph atlas room for 2x text: 1024 skyline nodes (128 cleared the atlas mid-frame), 8192 cached
  glyphs, and a full cache clears instead of dropping entries (they re-rasterized every frame until
  the atlas overflowed). A frame that clears the atlas requests another (`GlyphCache.evictions`):
  glyphs placed before the clear point at wiped or reused pixels (quick open drew garbage).
- Embedded images by name (`image.loader.embedded`): an image whose source names one decodes
  its bytes instead of reading a file (the welcome screen's logo).
